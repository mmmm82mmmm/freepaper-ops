# 納本システム ログイン設定手順

従業員NO + PIN でログインする仕組みの初期設定です。
**上から順に実施してください。** 所要時間は 30 分ほどです。

**移行モードを使うので、画面が止まる時間はありません。**
設定を進めている間も今まで通り使えます。切り替えの順番だけ守ってください
（下の「切り替えの手順」を参照）。

---

## 全体の流れ

```
[ブラウザ]  従業員NO + PIN
     │
     ▼
[Cloudflare Worker]  ← ここが唯一の関所
     │  ①名簿と照合  ②入館証を発行  ③以降は入館証を毎回検証
     ▼
[GAS 名簿API] → [スプレッドシート「名簿」]
     │
     ▼
[kintone]  納本(269) / マスタ(268)
```

ログイン画面を飛ばして直接ブックマークを開いても、入館証がなければ Worker が
データを返しません。**退職者の締め出しはここで効きます。**

---

## 1. スプレッドシートと名簿API（Google 側）

### 1-1. スプレッドシートを作る

1. Google ドライブで新しいスプレッドシートを作成
2. 名前を「**納本システム 作業員名簿**」などにする
3. 共有設定は**非公開のまま**にする（管理者だけが見られる状態）

> ⚠️ 「ファイル → 共有 → ウェブに公開」は**絶対に実行しないでください。**
> PIN が誰でも読める状態になります。

### 1-2. スクリプトを貼り付ける

1. スプレッドシートで **拡張機能 → Apps Script**
2. 既存のコードを全部消して、`gas/名簿API.gs` の中身を貼り付け
3. 保存（フロッピーのアイコン）
4. スプレッドシートのタブに戻って**再読み込み**すると、
   メニューバーに「**納本システム**」が現れます

### 1-3. 名簿シートを準備する

1. メニュー **納本システム → 名簿シートを準備**
2. 初回は権限の確認画面が出ます。
   「詳細」→「（プロジェクト名）に移動」→「許可」と進んでください
3. 「名簿」シートが作られ、見出しとチェックボックスが設定されます

> **すでに古い形（「役割」列に文字で書く方式）で作り始めていた場合**
>
> どちらでも動きます。急いで直す必要はありません。
>
> - **今のまま使う** … 「役割」列に `作業者・運転手` のように中黒でつないで書けば
>   兼務も表せます。何もしなくて構いません。
> - **チェックボックス方式に変える** … 新しい `gas/名簿API.gs` を貼り直してから
>   「名簿シートを準備」を実行します。データが入っていると確認画面が出るので
>   ［はい］を選ぶと、今のシートが「**名簿_旧**」として残り、新しい「名簿」が
>   作られます。従業員NO・氏名・PIN をコピーし、役割はチェックを付け直してください。
>
> 名簿がまだ数人なら、作り直したほうが後々分かりやすいです。

### 1-4. 合言葉を作る

1. メニュー **納本システム → 合言葉(ROSTER_KEY)を作成**
2. 表示された文字列を**コピーして控えておく**（後で Cloudflare に登録します）

### 1-5. ウェブアプリとして公開する

1. Apps Script 画面で右上の **デプロイ → 新しいデプロイ**
2. 歯車アイコン → **ウェブアプリ** を選択
3. 設定：
   - 説明：`名簿API`
   - **次のユーザーとして実行：自分**
   - **アクセスできるユーザー：全員**
4. **デプロイ** を押す
5. 表示された **ウェブアプリの URL** をコピーして控える
   （`https://script.google.com/macros/s/……/exec` の形）

> 「アクセスできるユーザー：全員」に不安を感じるかもしれませんが、
> 合言葉（ROSTER_KEY）が一致しないと名簿は返しません。
> Cloudflare Worker からは合言葉を付けて呼び出します。

## 2. Cloudflare 側

> ダッシュボードが日本語表示の場合の項目名を併記しています。
> Cloudflare は画面の文言がよく変わるので、**日本語名で見つからなければ
> 括弧内の英語名**を探してください。

### 2-1. KV 名前空間を作る

1. Cloudflare ダッシュボード左メニュー →
   **ストレージとデータベース（Storage & Databases）** → **KV**
2. **名前空間を作成（Create a namespace）** → 名前は `freepaper-auth`

作成後に「**現在エントリーはありません**」と表示されますが、**これで正常です。**
中身（名簿のキャッシュと PIN 失敗回数）は Worker が自動で作ります。
**手でエントリーを追加しないでください。**

### 2-2. KV を Worker に紐付ける（バインディング）

作った名前空間を、Worker から `AUTH_KV` という名前で使えるようにします。
**この作業は KV の画面ではなく、Worker の画面で行います。**

1. 左メニュー → **Compute（Workers）** または **Workers と Pages** → `kintone-proxy`
2. **設定（Settings）** タブ → **バインディング（Bindings）**
3. **バインディングを追加（Add binding）** → **KV 名前空間（KV namespace）**
   - 変数名（Variable name）： `AUTH_KV` ← **この名前でないと動きません**
   - KV 名前空間（KV namespace）： `freepaper-auth`
4. 保存する

> 設定を変えた後、**デプロイ（Deploy）** が必要な場合があります。
> ボタンが出たら押してください。

### 2-3. 署名鍵を作る

入館証の偽造を防ぐ鍵です。PowerShell で以下を実行し、出てきた文字列を使います。

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

### 2-4. シークレットを登録する

`kintone-proxy` → **設定（Settings）** → **変数とシークレット（Variables and Secrets）**
→ **追加**

「環境変数を追加」というダイアログが開きます。**キー**と**値**を入れ、
**値の右にある「シークレット」チェックボックスにチェックを入れます。**
左下の **「+ 追加」** で行を増やして、3 つまとめて登録できます。

| キー | 値 | シークレット |
|---|---|:--:|
| `AUTH_SECRET` | 2-3 で作った文字列 | ☑ |
| `ROSTER_URL` | 1-5 のウェブアプリURL（`/exec` で終わるもの） | ☑ |
| `ROSTER_KEY` | 1-4 の合言葉（40 文字） | ☑ |

3 行そろうとボタンが「**変数を3個追加**」に変わります。押したあと **デプロイ** します。

- `TOKEN_NOHON` と `TOKEN_MASTER` は既に登録済みなので触りません。
  **追加するのは上の 3 つだけ**です。
- 「シークレット」にチェックを入れると、保存後は値が見えなくなります。
  これが正しい状態ですが、**後から確認できないので値は手元に控えておいてください。**

### 2-5. 移行モードを有効にしてから Worker を更新する

いきなり切り替えると、画面が動かない時間ができます。
**移行モードを使えば、止めずに切り替えられます。**

1. **設定（Settings）** → **変数とシークレット** に
   `LEGACY_ALLOW` = `1` を追加する（シークレットにしなくて構いません）
2. `cloudflare-worker/kintone-proxy.js` の中身を全部コピーして、
   `kintone-proxy` の編集画面（**コードの編集 / Edit code**）に貼り付け、
   **デプロイ（Deploy）**

`LEGACY_ALLOW` が入っている間は、入館証を持たない今までの画面も
そのまま通ります。**この時点では何も止まりません。**

---

## 切り替えの手順（ここが本番）

上の 1 と 2 が終わっている前提で、次の順に進めます。

### 手順1　ログイン対応のHTMLを公開する

`auth.js` と、各画面に 1 行追加したものを push します。
GitHub Pages に反映されると、画面を開いたときにログイン画面が出ます。

### 手順2　実際にログインできるか確かめる

自分の従業員NO と PIN でログインしてください。**ここが一番の関門です。**

うまくいかない場合、原因はたいてい次のどれかです。

| 症状 | 原因 |
|---|---|
| 「名簿を確認できませんでした」 | `ROSTER_URL` か `ROSTER_KEY` が違う／GASが未デプロイ |
| 「従業員NO または PIN が違います」 | 名簿シートの入力内容を確認 |
| 「Worker の設定が未完了です」 | シークレットか KV バインドの登録漏れ |

**この時点で行き詰まっても、慌てる必要はありません。**
`LEGACY_ALLOW` がまだ効いているので、HTMLの公開を取り消せば
（`git revert` するか、一つ前のコミットに戻す）すぐ元通りに動きます。

### 手順3　移行モードを外す

ログインできることを確認したら、**`LEGACY_ALLOW` を削除して再デプロイ**します。
これで入館証のないアクセスは通らなくなり、切り替え完了です。

> ⚠️ **手順3をやるまでは、URLを知っていれば誰でもデータを読み書きできる状態のままです。**
> 確認が済んだら必ず削除してください。

### 元に戻したくなったら

`LEGACY_ALLOW` = `1` を入れ直して再デプロイすれば、
ログインなしでも通る状態に戻ります。HTMLはそのままで構いません。

## 3. 名簿に登録する

スプレッドシートの「名簿」シートに全員分を入力します。

| 従業員NO | 氏名 | PIN | 作業者 | 運転手 | 管理者 | 在籍 |
|---|---|---|:--:|:--:|:--:|:--:|
| W001 | 山田太郎 | 4728 | ☑ | ☐ | ☐ | ☑ |
| W002 | 鈴木花子 | 3910 | ☑ | ☑ | ☐ | ☑ |
| W003 | 田中三郎 | 8102 | ☐ | ☑ | ☐ | ☑ |
| A001 | 佐藤次郎 | 5561 | ☐ | ☐ | ☑ | ☑ |

- **従業員NO** … 現場は `W` から、事務・管理は `A` から。3 桁の連番（`W001` / `A001`）
- **PIN** … 4 桁の数字。管理者が割り振る。`1234` `0000` など推測しやすい並びは避ける
- **作業者 / 運転手 / 管理者** … 該当するものすべてにチェック。**兼務できます**
  （上の例の鈴木さんは、作業も運転もする人）
- **在籍** … 在籍中はチェックを入れる。**退職したらチェックを外す**（行は消さない）

### 役割でできることの違い

| | 作業者画面 | 運転画面 | 管理画面 | レコード一括削除 |
|---|:--:|:--:|:--:|:--:|
| 作業者 | ○ | **×** | ○ | × |
| 運転手 | ○ | ○ | ○ | × |
| 管理者 | ○ | ○ | ○ | ○ |

- **運転画面（driver.html）は運転手と管理者だけ**が開けます。
  作業者だけの人がメニューを見ると、運転画面のリンクは表示されません。
  URL を直接開いた場合は「この画面は使えません」と案内が出ます。
- 兼務している人（作業者と運転手の両方にチェック）は、当然どちらも開けます。
- 制限する画面を増やしたい時は、`auth.js` の先頭にある `PAGE_ROLES` に
  1 行足すだけです（例：`'補充作業.html': ['運転手', '管理者']`）。

編集は**保存不要**です。Google スプレッドシートは自動保存され、
Worker は 5 分ごとに名簿を見に行きます。

## 4. 動作確認

1. `https://mmmm82mmmm.github.io/freepaper-ops/` を開く
2. ログイン画面が出る → 自分の従業員NO と PIN を入れる
3. メニュー画面が表示され、各画面が今まで通り動く
4. **締め出しの確認**（重要）：
   - 名簿で自分の「在籍」のチェックを一時的に外す
   - 5 分待ってから画面を再読み込み
   - 「このアカウントは現在ご利用いただけません」と出れば成功
   - 確認できたら「在籍」のチェックを戻す

うまくいかない場合は、ブラウザの検証ツール（F12）の Console と Network に
Worker からのメッセージが出ています。設定漏れは名前付きで表示されます。

## 運用

### 退職した人が出たら

名簿の「**在籍**」のチェックを外すだけです。**遅くとも 5 分後**にアクセスできなくなります。
行は消さないでください（過去の作業記録との突き合わせに使います）。

### PIN を忘れた人が出たら

管理者が名簿を見て本人に伝えてください。PIN は名簿にそのまま書かれています。
変更したい場合は、名簿の PIN 欄を書き換えるだけです（本人は次回から新しい PIN でログイン）。

### PIN を 10 回間違えてロックされたら

30 分待てば自動的に解除されます。急ぐ場合は正しい PIN を伝えてください。

### 役割を変えたら（作業者に運転手を足したなど）

名簿を直したあと、**本人に一度ログアウトして入り直してもらってください。**
メニューの下にある「**別の人に切り替え**」から抜けて、もう一度ログインするだけです。

画面の出し分け（運転画面を表示するかどうか）はログイン時の情報を使っているため、
名簿を変えただけでは切り替わりません。

> 退職（在籍のチェックを外す）だけは別扱いで、**入り直さなくても 5 分で効きます。**
> 締め出しは急ぐ必要があるため、Worker 側で毎回確認しています。

### 人を替えて使いたい時（共有端末など）

メニュー下部の「**別の人に切り替え**」を押すとログアウトします。
次の人が自分の従業員NO と PIN でログインしてください。

### 名簿API（GAS）のコードを直したら

**保存しただけでは、公開中のウェブアプリに反映されません。**
必ず新しいバージョンとしてデプロイし直してください。

```
デプロイ → デプロイを管理 → 鉛筆アイコン（編集）
→ バージョン：「新バージョン」→ デプロイ
```

URL は変わらないので、Worker の設定はそのままで構いません。

> ⚠️ 見落としやすい落とし穴です。スプレッドシートのメニュー
> （名簿シートを準備など）は編集中の最新コードで動くのに、
> Worker から呼ばれるウェブアプリは古いままになります。
> 結果、名簿シートは新しい形なのに読む側が古い、という
> ちぐはぐな状態になり、**全員の役割が「作業者」になる**
> といった症状が出ます。

反映されたかどうかは、ログインし直して画面下部の役割表示で確認できます。

### 新しく人が入ったら

名簿に 1 行足すだけです。従業員NO は連番の続き、PIN は 4 桁を割り振ってください。

### ログインし直してほしい時

入館証の有効期間は **90 日**です。それまでは PIN の再入力は不要で、
ホーム画面のアイコンから開くだけで使えます。

## 仕組みのメモ（技術者向け）

- 入館証は HMAC-SHA256 署名付きの `payload.signature` 形式。`AUTH_SECRET` で署名。
  ブラウザの localStorage（`fp_auth_token`）に保存されます。
- `auth.js` が `window.fetch` を横取りし、Worker 宛のリクエストにだけ
  `Authorization: Bearer …` を自動で付けます。既存の画面コードは無改造です。
- Worker は**毎リクエスト**で名簿の在籍を確認します（KV に 5 分キャッシュ）。
  入館証の有効期間が 90 日でも、退職の反映は 5 分で効きます。
- 名簿API が一時的に落ちた場合は 1 時間まで古い名簿でしのぎ、
  それを超えると通しません（安全側に倒す）。
- PIN 連続失敗は KV の `fail:<従業員NO>` で記録。10 回で 30 分ロック。
- 役割は複数持てます。名簿API は `roles` を配列（例 `["作業者","運転手"]`）で返し、
  Worker は `roles` に `管理者` を含むかどうかで判定します。
  旧形式（「役割」1 列に文字で書く）も読めるようにしてあります。
- レコード削除（DELETE）と、管理ツールでの kintone トークン手入力は
  `管理者` を持つ人だけに許可されます。ここは Worker で拒否しています。
- 画面ごとの制限（`PAGE_ROLES`）は `auth.js` による**画面側の案内**です。
  誤タップや取り違えを防ぐためのもので、詳しい人が回避することは可能です。
  データそのものの防御（入館証の検証・在籍確認・削除の禁止）は
  すべて Worker 側で行っているため、回避されても被害は出ません。
